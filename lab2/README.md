
ЛР 2 по ОС вар 8
Условие
Есть `K` массивов одинаковой длины. Необходимо сложить эти массивы и предусмотреть стратегию, адаптирующуюся под количество массивов и их длину (по количеству операций).
Что делает программа
`lab2.c` содержит последовательную и параллельную версии сложения массивов. Для потоков используется POSIX Threads. Ввод исходных массивов в условии не задан, поэтому программа заполняет их воспроизводимыми целыми числами от -100 до 100. Параметры `K` и `N` задаются командной строкой.
Параллельная версия использует один из двух способов распределения работы:
если длина результата позволяет дать каждому потоку отдельный диапазон индексов, потоки считают элементы результата;
если массивов больше, чем элементов результата, потоки считают частичные суммы по входным массивам, после чего главный поток объединяет частичные результаты.
Для последовательной версии и каждой конфигурации потоков измеряется медиана пяти запусков. Измерения пишутся в CSV, а итоговый массив — в `result.txt`. Перед сохранением программа сверяет параллельный результат с последовательным.
В коде не используются `stdio.h`, `stdlib.h`, `string.h`, `threads.h`, `stdatomic.h`, функции `printf()` и `malloc()`. Вывод и файлы обрабатываются через `write()`, `open()`, `close()`, память выделяется через `mmap()`, потоки создаются через `pthread_create()`.
Сборка
```bash
make
```
То же самое напрямую:
```bash
cc -O2 -Wall -Wextra -Wpedantic -std=c11 -o lab2 lab2.c -pthread
```
Один опыт
```bash
./lab2 --arrays 8 --length 500000 --threads 4 --out result.txt
```
Параметры:
`--arrays K` — количество входных массивов;
`--length N` — длина каждого массива;
`--threads T` — ограничение на число рабочих потоков для одного опыта;
`--bench auto` или `--bench 1,2,4,8` — запуск серии опытов;
`--seed S` — начальное значение генератора;
`--out FILE` — куда записать результат;
`--csv FILE` — куда записать таблицу измерений.
Серия для отчёта
Сначала посмотри количество логических процессоров:
```bash
nproc
```
Затем запусти:
```bash
./lab2 --arrays 8 --length 1000000 --bench auto --csv timings.csv --out result.txt
```
Для систем, где доступно не менее 5 логических процессоров, автоматический план формирует минимум 8 разных конфигураций: четыре значения ниже числа логических процессоров, одно равное ему и три больших значения. Например, при 8 доступных логических процессорах план будет `1,2,4,7,8,16,128,1024`.
Если `nproc` показывает меньше 5, четыре разных значения меньше числа CPU выбрать невозможно. Программа выводит предупреждение и выполняет все возможные меньшие значения, значение равное числу CPU и три больших значения. В таком окружении нельзя полностью выполнить требование преподавателя к количеству экспериментов; для сдачи запусти серию на машине, где доступны 5 или больше логических процессоров, либо уточни это ограничение у преподавателя.
Время запуска и завершения потоков входит в измерение параллельного этапа. Входные данные генерируются до измерений. Ускорение вычисляется как `S = T_seq / T_par`, эффективность — как `E = S / P`, где `P` — фактическое число созданных потоков.
Проверка второй стратегии
```bash
./lab2 --arrays 20 --length 3 --bench 1,2,4,8 --csv small.csv --out small.txt
```
При таком тесте `N` мало по сравнению с `K`; при запросе более чем `N` потоков программа использует разбиение по входным массивам.
Проверка количества потоков средствами ОС
Для более длительного запуска открой второй терминал:
```bash
./lab2 --arrays 8 --length 2000000 --threads 128 --out result.txt &
pid=$!
ps -T -p "$pid"
wait "$pid"
```
Количество строк, отображённых `ps -T`, может зависеть от момента выполнения команды. Запуск с большим `N` нужен, чтобы процессы успели появиться к моменту проверки.
CSV
В `timings.csv` записываются `arrays`, `length`, запрошенное и фактическое число потоков, время параллельной и последовательной версий в миллисекундах, ускорение, эффективность и выбранная стратегия. Для отчёта переноси значения из CSV, полученного на своём компьютере.
